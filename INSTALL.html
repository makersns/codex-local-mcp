SUGAR LOCAL MCP DESKTOP

本机开发，直接连接 ChatGPT

Sugar 读写代码、运行前后端与测试；已连接的 ChatGPT Chrome 集成负责网页调试。

0.5.0 · macOS

首次安装，五步完成

  1. 完整解压，双击 App

    打开 Sugar Local MCP Desktop.app。它安装到当前用户的 ~/Applications，并在可用时创建桌面入口。以后直接双击即可。

  2. 等待运行环境准备

    首次需要联网下载 Python、MCP 依赖与缺少的官方隧道组件；无需创建虚拟环境。项目自己的 Node、Java、数据库等仍使用本机安装。

  3. 填写这台 Mac 的连接信息

    输入电脑名称、专属 Tunnel ID 和 Runtime API key。key 在隐藏框输入，保存在本机登录钥匙串，不需要发送到聊天。

  4. 添加项目目录与权限

    添加一个或多个目录，为每项设置文件写入与命令执行权限，核对后保存并连接。新项目默认可写、可执行。

  5. 在 ChatGPT 验证调用

    选择对应 Sugar 插件，让它列出工作区并读取一个 README。“本机隧道已就绪”是本地状态，实际工具调用成功才确认完整链路。

如果预编译 App 无法使用，保留完整 Source 文件夹，双击 Install_Sugar_Local_MCP.command。这是一次性重建安装入口，会显示终端进度，无需输入命令。

在哪里取得 key 和 ID

在 OpenAI 隧道设置 创建或选择隧道，关联目标 ChatGPT 工作区，再从 API keys 管理适用的 Runtime key。

运行身份需要该隧道的 Tunnels Read + Use 权限。每台 Mac 使用不同 ID，同一 stdio 隧道保持一个活动客户端。

本应用连接已有隧道，不代替创建平台隧道或 ChatGPT 插件。

前后端可以分别添加

共同根目录下的前后端，添加一个根目录即可。在不同位置时，分别添加 frontend 和 backend。

通过“配置 → 管理项目目录”继续添加、换目录、调整权限或移除条目。移除不删除本机代码。

保存变更会重启托管连接；先完成正在运行的任务，再让 ChatGPT 重新查询工作区。

用 Chrome 集成完成本地联调

同一聊天中使用目标 Mac 的 Sugar 插件与 Chrome 集成：Sugar 启动项目、读取日志并改代码，Chrome 集成打开实际开发地址、操作表单并检查结果。

检查 frontend 与 backend 的启动说明，启动并确认服务就绪；确认 Chrome 连接的是同一台 Mac，打开前端页面，检查交互与控制台，修复代码后重新测试。
两条连接需要对应同一台 Mac。 切换 Sugar 插件不会自动切换 Chrome 设备。开始前用目标 Mac 上含唯一标记的 127.0.0.1 测试页核对，不能只凭两边都显示 localhost 判断。

这个流程无需授予 Sugar 屏幕录制或辅助功能。App 保留手动“系统权限检查（可选）”；Chrome 连接由 ChatGPT 独立管理。

日常入口与升级

需要做什么App 中的入口
保持后台在线状态窗口点“完成”，连接继续运行
重新启动后台配置 → 重启连接；只重开窗口可能复用旧后台
停止 Sugar状态窗口 → 停止连接；Chrome 集成独立管理
检查文档环境配置 → Office 环境检测与验证

升级保留项目、权限、隧道设置和钥匙串。重启连接后，在 ChatGPT 的 Plugins → 对应 Sugar 连接 → Refresh 刷新，再开新对话。写入与执行均启用时最多 15 个工具，纯只读时 4 个。网页操作使用 Chrome 集成。

实际使用范围

命令使用当前用户的真实本机权限；项目目录不是进程沙箱。Office 检测和验证覆盖基础文件样例，真实文档的版式、公式和 PDF 导出需要另行检查。本版不提供通用原生桌面输入。

当前是 ad-hoc 签名的个人应用，未提供 Apple Developer ID 公证。若系统阻止打开，在确认来源后使用系统“隐私与安全性”允许打开。首次安装需要网络；没有提供离线依赖包。
