# Codex Local MCP 会话活动监测设计

核查日期：2026-11-23（Asia/Shanghai）

状态：设计记录，尚未实施。

适用基线：Codex Local MCP 0.6.0；固定 MCP Python SDK 2.3.0。

## 1. 结论与范围

Codex Local MCP 0.6.0 尚未实现 ChatGPT 会话活动统计。0.5.0 基线也没有这项功能，不能把本轮原生界面重构描述为已经恢复或完成了会话计数。

官方插件参考文档提供请求元数据 `_meta["openai/session"]`，用于以匿名会话标识关联同一个 ChatGPT 会话的工具调用。现有固定 SDK 可以接收和读取这个字段，因此可以实现“正在调用的会话”和“最近活跃会话”统计。

该字段只随请求提供，不代表聊天窗口持续在线。当前链路没有可用于本功能的聊天关闭、解除连接或持续心跳事件，因此不得把活动统计标为“精确在线会话数”。

本文件只记录设计，不修改服务、不采集真实会话标识、不更改现有权限，也不启动或重启连接。

| 位置 | 当前行为 | 对会话统计的含义 |
| --- | --- | --- |
| `server/src/sugar_local_mcp/server.py` | 工具函数没有注入 MCP Context；统一 `invoke()` 未读取请求元数据 | 尚未按 ChatGPT 会话关联调用 |

## 3. SDK 2.3.0 的读取方式

工具通过 Context 类型注入获取协议上下文。Context 属于 SDK 注入参数，不应新增一个由模型自行填写的公开“会话 ID”工具参数。

以下仅为后续实现示例，未加入服务代码：

```python
from mcp.server.mcpserver import Context

def conversation_id_from_context(ctx: Context) -> str | None:
    meta = ctx.request_context.meta
    if not isinstance(meta, dict):
        return None
    value = meta.get("openai/session")
    if not isinstance(value, str) or not value:
        return None
    return value
```

本机固定 MCP SDK 2.3.0 中，`ctx.request_context.meta` 实际为 `dict`，应直接读取；不要对它调用 `model_dump()`。

已用虚构数据验证：

1. `CallToolRequestParams.model_validate()` 可以保留 `_meta` 中的 `openai/session`。
2. 通过 Context 的 `request_context.meta` 可以读回该虚构标识。
3. 本次核查未拦截真实请求、未输出真实会话 ID，也未改变正在运行的服务。

该验证证明 SDK 的字段兼容性。未来正式实施还需验证当前隧道转发链路确实保留此元数据；未验证前不得把真实会话统计标为已可用。

## 4. 建议的概览指标

概览页建议显示紧凑的“连接活动”区域：

| 指标 | 定义 | 显示原则 |
| --- | --- | --- |
| 正在调用的会话 | 当前至少有一个尚未结束的工具请求，且带有有效会话标识的不同会话数 | 同一会话多个并发请求只计一个会话 |
| 最近 10 分钟活跃会话 | 最近 10 分钟内发起过工具请求，且带有有效标识的不同会话数 | 时间窗口必须直接写在标签中 |
| 运行中任务 | 本机受管命令中仍在运行的任务数 | 与工具调用数和会话数分开 |
| 最近活动 | 最近一次远端工具调用的时间、操作名称及相关工作区 | 不显示调用内容、命令参数或文件正文 |

“最近 10 分钟”是首期建议值，并非协议规定。窗口应由统一配置常量控制，避免不同页面使用不同口径；首期无需增加一个必须由普通用户配置的表单。

会话明细可显示本次服务运行期间的本地匿名编号、最近活动时间、正在执行的工具调用数及相关工作区。不要假设能够获得聊天标题、聊天内容或真实用户身份。

连接可用但没有活动时，显示“最近 10 分钟暂无工具调用”。缺少会话元数据时，显示“会话来源尚未识别”，不能显示成“0 个会话已连接”。

## 5. 统计口径与边界

### 5.1 未识别来源

未携带字段、字段类型错误或字段过长的请求，仍正常执行原工具逻辑。

这些请求纳入“来源未识别的调用”计数及最近活动信息，但不纳入已识别的不同会话数。不能把所有未知请求合并成一个已知会话，也不能按请求数量推测有多少个未知会话。

如同时存在已识别和未识别的调用，应显示已识别统计及“另有未识别来源的调用”，避免给人统计覆盖全部调用的错觉。

### 5.2 当前调用与最近活跃

当前调用计数在请求进入时增加，并在完成、错误或取消时可靠减少。应使用 `try/finally` 与一致的并发保护，避免异常后残留“正在调用”。

最近活跃时间使用单调时钟进行窗口计算，避免系统时间调整导致会话突然全部过期或长期不消失；展示给用户的时间另存为墙上时钟时间。

没有新调用只说明该会话在观察窗口内未活动，不能证明用户关闭了聊天或断开了连接。

### 5.3 服务重启与统计起点

活动注册表只在内存保存。服务重启后重新开始统计，并返回本次服务的启动时间或统计起点。

界面应明确“本次连接启动后统计”。发生重连或后台进程更换时，不把旧数据继续显示为当前活动，也不把暂无数据解释成历史从未使用。

### 5.4 任务与会话分离

`run_command` 返回后，工具请求已经结束，但该命令可能继续运行。因此：

- “正在调用的会话”按未结束的工具请求计算。
- “运行中任务”按受管进程真实状态计算。
- 长期运行的服务或命令不会让发起会话永久被判为在线。
- `process_list.total` 包含保留的已结束任务，不能直接作为运行中任务数。
- 本地 GUI 的状态轮询和诊断查询不能计入远端 ChatGPT 会话活动。

## 6. 最小实现结构

### 6.1 服务内存注册表

在 MCP 服务进程中增加一个有界、线程安全的活动注册表，统一记录：

- 本次服务启动标识和统计起点。
- 会话的本地匿名键、本地编号、首次和最近活动时间。
- 当前工具请求数，以及必要的操作名称和工作区摘要。
- 来源未识别的当前调用数、最近调用数。
- 有界统计是否完整，防止超出容量后仍把部分值当作精确总数。

内存中的会话键建议使用每次启动随机生成的密钥，对官方匿名会话标识进行 HMAC 摘要后保存。原始标识仅在处理当次请求时读取，不写入注册表、日志、磁盘文件或界面。启动密钥只存在内存，重启后不尝试跨运行期追踪同一会话。

注册表需要按时间清理空闲记录，并设置合理容量上限。超过容量时应返回“统计不完整”状态，界面显示清楚的覆盖限制；不能静默丢记录后仍声称是全部会话数。当前尚未结束的请求应优先保留。

### 6.2 统一调用入口

在工具入口获取 Context，经统一 helper 提取并校验元数据，再将匿名键传入现有 `invoke()` 的统计包装层。

元数据仅用于活动展示，不能作为认证依据、文件权限依据或任务所有权授权依据；原有工作区权限和进程管理规则不变。

不得把 JSON-RPC request ID、隧道 ID、transport session ID 或进程 PID 当作 ChatGPT 会话 ID。

### 6.3 原生界面查询

复用现有本机诊断通信机制，增加只读、有限长度的活动快照能力，再由桌面 JSON API 提供给原生界面。不新增公开网络监听端口。

返回内容只包含计数、时间、匿名编号和受限摘要，并包含数据可用性、统计窗口及本次运行标识。界面仅在可见时刷新；后台不可达时展示“暂时无法更新”，不能保留旧数值冒充实时数据。

## 7. 实施时的必要验证

后续若授权实施，应围绕真实统计风险完成验证：

- 同一会话的顺序与并发调用去重；不同会话分开计数。
- 成功、异常、取消后，当前请求和当前调用会话数均正确归零。
- 缺失、非法或过长元数据按未知来源处理，不影响原工具执行。
- 时间窗口过期、系统时间调整、服务重启和注册表容量上限有清楚结果。
- 长命令与工具请求生命周期分离，本地 GUI 查询不增加远端活动数。
- 单次真实链路验收仅记录字段存在性和聚合结果，不记录真实会话标识或聊天内容。

本节是后续验收范围，不表示上述功能已经实现或测试通过。
