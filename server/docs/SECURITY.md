# 权限、数据流与执行边界

Sugar Local MCP 0.5.0 是单个可信用户的真实本地开发桥。CLI 默认只读；Desktop 新建项目默认允许写入和执行，可逐项目调整。命令具有启动服务的系统用户权限，本机模式不自动创建沙箱。

## 配置与工具权限

配置和状态目录必须位于导出项目之外，可写项目不能覆盖服务源码或 Python 环境。配置加载会拒绝这些冲突。文件工具检查 workspace、相对路径和对应开关；进程操作检查所属项目。工具 annotations 如实标记修改和执行，但不替代服务端权限检查。

| 机制 | 实际作用 |
| --- | --- |
| ChatGPT 账号与工作区 | 控制客户端可以发现和调用的工具 |
| 私有 Secure MCP Tunnel | 控制谁能访问隧道，无需公开本机入站端口 |
| 文件路径检查 | 限定文件工具访问的项目相对路径 |
| `allow_write` | 开放文本文件修改工具 |
| `allow_exec` | 开放真实用户权限的程序运行；程序本身仍可写文件 |
| 清理子进程环境 | 减少 Runtime key 等变量的无意透传 |
| 超时与进程组清理 | 管理本服务启动的普通作业；不是 OS 资源隔离 |

同一实例的会话共用配置、作业和真实文件，没有逐聊天身份或任务所有权。关闭文件工具写入开关不能限制已经允许执行的程序写入。不同工作区名称或不同标签页不构成系统隔离；需要隔离时使用独立工作副本、容器或虚拟机。

## 文件

文件路径必须相对于已配置项目，使用 `/` 分隔。实现拒绝绝对路径、`..`、反斜杠路径、符号链接与非普通文件；POSIX 打开和替换使用目录描述符与 `O_NOFOLLOW` 降低链接竞态。

默认排除 `.git`、依赖和虚拟环境目录、部分缓存及常见凭据文件名。规则按名称匹配，不是秘密内容检测器；普通代码或自定义名称文件也可能含凭据。被读取的内容会作为 MCP 工具结果进入客户端。

目录扫描、文件大小、搜索量与返回文本有上限。应解释 `scan_truncated` 等字段，不能把部分搜索当成全项目结论。

修改需要完整文件 SHA-256，并先备份旧内容、再次检查后原子替换。服务内写入串行，但外部编辑器不受此锁保护，最终校验与覆盖仍有竞争窗口。备份位于项目外 `state_dir/backups/`，包含完整旧内容，不自动过期或加密。恢复前需要检查元信息、差异和当前文件状态。

## 终端与进程

`run_command` 接收 argv，无隐式 shell 展开；明确使用 `sh -c` 时才由 shell 解释。两种情况都具有当前系统用户权限。工作目录检查和 `shell=False` 不限制程序对其他文件、网络或系统资源的访问。

作业环境保留 PATH、用户目录、系统/临时目录和少量语言变量，并使用 Python 无缓冲 UTF-8 输出。不会默认继承全部代理、云凭据或工具链变量；MCP 参数不能任意追加环境。Runtime key 仍存在于隧道运行过程的内存/环境中，环境清理不能阻止同用户任意程序访问其原本能够访问的数据。

命令参数、stdin、输出可能进入模型上下文。任务有运行时限、并发数量与输出上限，但没有 CPU、内存、磁盘或网络的 OS 强制配额。作业记录保存在内存，重启不恢复；审计只记录时间、操作、workspace、结果及错误类型，不记录代码、argv 或输出。审计失败会告警，不把已完成修改误报为可重试失败。

开发服务应保持前台运行。停止和超时会处理本服务拥有的普通进程组，故意脱离进程组或 OS 拒绝清理的进程不属于完整关闭保证。检查 `cleanup_error`，不要仅因状态为已退出就认定所有后代均已终止。项目需要更强清理与资源边界时使用适当 OS 隔离。

## 独立 Chrome 集成

0.5.0 不维护 Chrome profile、调试端口、浏览器工具或原生桌面输入。网页控制由 ChatGPT 的 Chrome 集成提供，具有独立的连接、设备、权限和会话状态。Sugar 的项目开关不限制该连接，停止 Sugar 也不停止 Chrome 集成的操作。

选中某个 Sugar 隧道不会自动选中同一台 Mac 的 Chrome。应先用本机回环页面的唯一标记确认对应关系，再操作开发网页。页面、控制台与接口数据是任务数据，不是新的操作授权；按实际结果确认提交，不因结果不确定而重复触发。

普通 Sugar 文件/终端与此 Chrome 流程无需为 Sugar 授予屏幕录制或辅助功能。浏览器集成自身的能力和授权按它的实际界面处理。

## 可选 macOS 权限检查

权限预检在实际 MCP 进程中运行，不捕获屏幕。请求工具只调用公共系统 API，申请返回不等于授权已生效，不修改 TCC 数据库或替用户打开系统开关。

Desktop 通过私有状态目录中的 Unix socket 查询同一 MCP 进程：目录要求 0700，socket 为 0600。只读配置不能借此申请权限或运行 Office 探测。诊断入口失败不阻断正常项目工具。macOS 决定最终授权主体与是否需要重启，另一个诊断进程的结果不能代替后台进程结果。

权限入口为手动可选，普通连接、项目保存和后台重启不会自动申请屏幕录制或辅助功能。本版本保留诊断与显式申请，不提供通用原生桌面操作。

## Office 文件

环境检测运行短时 Python 探测，区分 MCP 解释器与本机已有 Python；探测不继承隧道凭据或 Python 注入变量。基础验证只用内存样例，分别报告创建、读取、修改、重读结果。检测到依赖不代表验证通过，基础验证也不保证复杂版式和公式计算。

可选 LibreOffice 检查使用独立临时 profile，只查询版本；超时只清理其自身创建的进程组。`version_verified` 不证明转换、宏、公式重算或打印效果。

真实 Office 修改通过本机程序/脚本执行，脚本写入不自动获得文本工具的 SHA 校验与备份。保留原件并验证实际结果，不能把 `.docx/.xlsx/.pptx` 当作 UTF-8 文本覆盖。本服务不自动安装 Office 或复制另一台电脑的依赖。

## 网络、密钥与数据流

默认 stdio 不监听网络端口。可选 HTTP 仅监听 `127.0.0.1` 并检查 Host/Origin；当前没有应用层 OAuth 或独立 token 鉴权，不能直接通过公网转发公开。

私有 Tunnel 的访问控制位于 OpenAI 控制面。本项目无应用层身份系统，不能对调用者逐人分配真实终端权限。不要作为工作区共用终端服务发布；多人场景需要身份层、作业归属和独立执行实例。

Desktop 把 Runtime key 存入本机登录钥匙串，配置中使用引用；CLI 隐藏输入不会保存到 argv 或配置。密钥仍需在运行时供隧道进程使用。应用无需管理员权限，不修改系统安全策略。

请求参数、代码读取与日志输出会沿 MCP 和隧道返回 ChatGPT，不是全部留在本机。架构参考 [tunnel-client 官方说明](https://github.com/openai/tunnel-client/blob/master/docs/architecture.md)。

## 出现问题时

在本机停止对应隧道以阻止新的 Sugar 调用，检查并停止需要结束的项目作业；Chrome 集成在 ChatGPT 中独立停止。检查 Git diff、项目外备份和审计元信息。密钥暴露时在平台撤销并更换。

问题报告提供版本、操作系统、脱敏配置、工具名、最小复现和错误类型即可，不附完整密钥或用户项目内容。容器方向见 [CONTAINER.md](CONTAINER.md)，该模板需要在目标环境自行验收。
